## Purpose

DocuMe is a distributable docs-lifecycle toolkit: a Claude Code skill generates a verified markdown wiki from a codebase, a deterministic .NET CLI (`docume`) publishes it to Confluence Cloud and keeps it in sync, and label/comment-driven loops handle approval, feedback, and drift-refresh. Evidence: `PLAN.md` §1.

## Users

Development teams at Moberg/Kvika who keep documentation in their repos and publish to Confluence for teammates and reviewers. Customer #1 is the AurServices team (79-page wiki, Confluence space `AUR` on kvika.atlassian.net). Evidence: `PLAN.md` header, §1.

## Key flows

- **Generate** — `/docs-loop` builds a verified markdown wiki from the codebase (code is ground truth). Evidence: `PLAN.md` §1, §11.
- **Publish** — `docume publish` converts markdown → Confluence storage format (hierarchy, Mermaid SVGs, link rewriting) and upserts pages/attachments. Evidence: `PLAN.md` §6.2, §7.
- **Approve** — teammates add an `approved` label; `docume sync` records approval per page version; content changes invalidate it. Evidence: `PLAN.md` §8.
- **Feedback** — Confluence comments → normalized inbox → `/docs-feedback` verifies each claim against code → fix PR → reply to commenter. Evidence: `PLAN.md` §9.
- **Refresh** — deploy triggers `docume drift --mark` (stale labels); nightly `/docs-refresh` regenerates stale pages as a PR. Evidence: `PLAN.md` §10.
