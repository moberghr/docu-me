01 The commands seven

Seven commands, and only four can write.

The root command carries nothing but --help and --version; every option below belongs to one command. A bare invocation prints the command list rather than exiting silently.

Running the pinned tool dotnet tool run keeps -?, -h and --help for itself, so dotnet tool run docume --help prints the SDK's help and never reaches DocuMe. Put -- ahead of the arguments to forward them through: dotnet tool run docume -- drift --help. --version is not one of the wrapper's options and needs no --.

Every command that reads docume.json takes --config (default docume.json), and its directory is the repo root that the wiki root and every sources glob resolve against. Every command that reads state takes --state, defaulting to the state file inside the wiki root.

docume init

Scaffolds a consumer repo: docume.json, the wiki skeleton with its style guide, the mermaid renderer, the six workflow templates, a tool manifest, a .gitignore entry. Thirteen targets, and it is idempotent — an existing file is never overwritten, and every skip is reported.

OptionEffect
--spaceConfluence space key written into docume.json
--base-urlConfluence wiki base URL written into docume.json
--adoptBuild the state file from the wiki this repo already has, one entry per page, page ids seeded from frontmatter
--legacy-mapPath to a JSON page path → page id map from whatever published the wiki before. Requires --adopt

docume convert <wiki-root>

Converts every page and reports what happened, grouped by construct and by dialect. No credentials, no network, nothing written — not even the storage format it renders. Exit code 0 means the corpus clears the acceptance bar. This is the right pre-flight for CI on a pull request that touches the wiki.

OptionEffect
--accept <code>Treat a diagnostic code as an accepted loss: still reported, counted as a note instead of a warning. Repeatable
--render-mermaidAlso render every diagram through Node and report the ones that fail. Off by default: one process per diagram
--renderer <path>Path to the render script. Defaults to tools/render-mermaid.mjs

docume publish

Converts the wiki and publishes it: link map, mermaid attachments, storage-format conversion, content hashing, upsert, approval banner, open-comment guard, approval invalidation, orphan report, and a child-order pass that makes Confluence match the source tree. Parents before children.

OptionEffect
--dry-runPlan and print, write nothing
--treeAlso print the page tree the run would build
--forceRepublish every page even when nothing changed, re-uploading attachments
--changed-since <sha>Write only the pages touched since a commit, including pages whose images changed. The whole tree is still loaded, converted and checked for orphans
--page <path>Write only these pages. Repeatable; a path not in the tree is an error
--pruneDelete orphan pages after publishing. Asks first, needs a terminal, refuses to run in CI
--no-reorderSkip the pass that puts each parent's children in source-tree order
--block-on-open-commentsLeave a page alone and exit non-zero when it has unresolved inline comments a body rewrite could strand. Default is to publish and warn
--no-comment-checkSkip that read entirely
--notify-reviewersPost a footer comment asking for a re-review on every page whose approval the run revoked. One comment per revoked approval, so it reaches each page's watchers
--allow-protected-spaceWrite into a write-locked space, for one run
The one destructive option An orphan is a state entry whose markdown file is gone — which is also what a renamed file looks like before its new path is published. Prune after a successful full publish, never alongside a partial one.

docume sync

Reads labels and comments out of Confluence and reconciles them into the repo. Passing neither half runs both read halves. Committing the result is the caller's job; in CI that means a docs/sync pull request, so a human sees state changes before they land.

OptionEffect
--labelsReconcile the approved and stale labels into state
--commentsIngest page comments into the feedback inbox, behind a per-page cursor
--replyPost a reply under every triaged inbox item and resolve the inline comments it answers. The only half that writes to Confluence
--output-dirWhere to write inbox items. Defaults to the feedback inbox under the wiki's _meta
--dry-runReport what would change and write none of it

docume drift

Reports which pages derive from code changed between two revisions, with the matching pattern and files named so a reader can judge the report rather than trust it.

OptionEffect
--baseline <rev>Revision to diff from. Defaults to the recorded generation baseline
--head <rev>Revision to diff to. Defaults to HEAD
--format <shape>table, json, or github-comment. json prints nothing else
--fail-on-driftExit 1 when any page is affected. Without it the command is advisory and exits 0
--markAdd the stale label to affected pages, set the state flag, refresh the dashboard
--dry-runWith --mark: report what would be labelled, write nothing. Needs no credentials
--allow-protected-spaceWith --mark: label pages in a write-locked space, for one run

docume dashboard

Regenerates the status page from state plus the live labels. The labels are reconciled in memory here; sync --labels is what writes them into state.

OptionEffect
--titleTitle of the dashboard page. Defaults to the configured title
--dry-runPrint the storage format it would publish and write nothing
--allow-protected-spacePublish the dashboard into a write-locked space, for one run

docume status

Reports what is published, what drifted, and whether this repo is set up to publish at all. status --json is what every skill appends to its pull-request body, so a reviewer sees the state of the space next to the diff.

OptionEffect
--jsonPrint the report as JSON and nothing else, for a pull-request body or a CI step
--offlineSkip the single Confluence request — the token and space probe
--fail-on-driftExit non-zero when the published wiki differs from the repo
02 What writes where

Four write paths, all of them gated.

CommandWrites to ConfluenceWrites to the repo
initnothe scaffolded files
convertnonothing
publishpages, attachments, labelsthe state file
synconly with --replythe state file, the feedback inbox
driftonly with --markthe state file, with --mark
dashboardthe dashboard pagenothing
statusnonothing

Every write path in that table is gated on the protected-spaces list: name a space there and publish, dashboard, drift --mark and sync --reply all refuse it. The first three carry --allow-protected-space to lift the refusal for one run without editing the list.

sync --reply deliberately does not. A reply is a comment posted into a space this repo was told to stay out of, so there is no per-run override, and its read halves report the lock instead of refusing.

03 Configuration

One file, committed, and therefore free of secrets.

docume.json lives at the repo root. Three fields are required and validated on load: the Confluence base URL, the space key, and the wiki root. init writes a working file with all three set.

docume.json — an example, not a list of defaults
{
  "$schema": "https://raw.githubusercontent.com/moberghr/docu-me/main/schema/docume.schema.json",
  "confluence": {
    "baseUrl": "https://example.atlassian.net/wiki",
    "spaceKey": "DOCS",
    "spaceId": "2431647748",
    "rootPageId": "4512153602",
    "protectedSpaces": ["PROD"]
  },
  "wiki": {
    "root": "docs/wiki",
    "exclude": ["_meta/**"],
    "extraPages": [
      { "path": "_meta/GAPS.md", "title": "Open Questions for the Team" }
    ],
    "homePage": "README.md"
  },
  "labels": { "approved": "approved", "stale": "stale" },
  "dashboard": { "title": "Documentation Status" },
  "mermaid": { "renderer": "tools/render-mermaid.mjs" }
}

Four of those values are illustrations, and the real default for each is empty:

FieldActual defaultWhat the example shows instead
space idabsent — resolved from the space key on first usea numeric id
root page idabsent — publish under the space roota numeric id
protected spaces[] — no space is write-lockedone locked space
extra pages[]one re-included file

The home page names every index

Not only the root. a/b/page.md hangs under a/b/README.md, which hangs under a/README.md. A directory with no index page is skipped rather than synthesized: its children hang from the nearest index above it, because inventing a page no author wrote would break the one-way rule.

The write lock starts empty

A fresh init locks nothing. A listed space is refused, and the only way past it is --allow-protected-space for a single run. There is no config value that grants it permanently, so removing a lock is a reviewed commit rather than a flag somebody stops reading.

The schema line is the only check on a misspelled key The loader binds the keys it recognizes and drops the rest without a word. Write protectedSpace for protectedSpaces and the write lock is simply off, on every run, with nothing printed. The schema sets additionalProperties: false on every object, so a schema-aware editor flags the typo as you type it. That is the only place a misspelled key is ever reported.
Two fields are inert in this version A default-branch setting and a repo blob URL both load, validate and round-trip like every other field, and no command reads either one. They are documented rather than removed because both are declared in the build plan and one has a specified behaviour, so building them and dropping them are both still open. The suite fails if either field acquires a reader while the docs still call it inert.
04 State and frontmatter

Three files, three owners, all three committed.

FileOwnerCommitted
docume.jsonhumansyes
page frontmatterwhoever writes the pageyes
_meta/state.jsonthe toolyes

State is committed on purpose. It carries page ids, content hashes and approvals, so publishing from a different machine or a CI runner has to produce the same plan as publishing from a laptop.

Page frontmatter

KeyRequiredMeaning
sourcesno, but drift needs itCode paths the page derives from, as globs relative to the repo root
titlenoOverrides the title. Defaults to the first H1, which is dropped from the body because Confluence renders the page title itself
pageIdnoSet by publish. Pre-seed it to adopt a page that already exists in Confluence

Frontmatter is stripped before conversion, so none of it appears in the published body or in the content hash. Titles must be unique across the space, because a relative .md link converts to a Confluence link by title: two pages claiming one title fail the whole load with both paths named, rather than publishing a tree with an ambiguous link in it.

The two shas answer different questions

Generation baseline

The commit the wiki content was last generated against. Drift measures from here. No CLI command writes it — the generation pass does, which is /docs-loop or /docs-refresh.

Last published sha

The commit of the last publish run, written by publish, and what --changed-since reads. Using it as the drift baseline would report zero drift on any repo that publishes on every merge — which is every repo that has automated this properly.

05 The conversion contract

What converts, what degrades, what stops the run.

MarkdownConfluence
Headings h1–h4<h1>–<h4>, with the page's leading h1 dropped — Confluence renders the title itself
GFM tables<table> with a header row
Fenced code blocksThe code macro, with the language mapped where Confluence knows it
GitHub alertsPanel macros: NOTE and IMPORTANT to info, TIP to tip, WARNING to note, CAUTION to warning
Mermaid fencesRendered to SVG, attached to the page, referenced as an image
Relative .md linksA Confluence page link, resolved by the linked page's title
External linksA plain anchor
[TOC] alone on a lineThe table-of-contents macro
ImagesAttachment plus image tag; a width attribute becomes the rendered width
Task listsThe native task-list macro
Inline code, bold, italic, strikethrough, blockquotes, rules, nested listsNative markup

The seven degradation codes

A degradation converts, with something lost, and says so. Each is reported per page with the dialect that triggered it, and each can be promoted to a note with --accept — which keeps the count and the breakdown in the report rather than hiding them.

CodeWhat is lost
unknown-fence-languageHighlighting for a language outside the brush map, which takes both Atlassian's documented list and a Prism component id. Being documented is not enough on its own
mixed-task-listA list mixing task and plain items falls back to a plain list, echoing the literal [x] text
same-page-anchor-linkThe destination. An anchor link within one page publishes as its plain link text
table-alignment-droppedCentered or right column alignment, reported once per column. An explicitly left column publishes the way GitHub renders it and stays silent
ordered-list-start-droppedA list starting at something other than 1
alert-type-collapsedThe emphasis on [!IMPORTANT], which shares the info panel with [!NOTE]
task-list-numbering-droppedAn ordered task list, which the macro cannot number

Code fence attributes

Fence attributes are space-separated with no = anywhere. title takes the rest of the line, unquoted; collapse, nocollapse, linenumbers and a bare positive integer for firstline are the other four.

An unrecognized attribute fails the page loud Including the title=Foo spelling, which is a different tool's syntax. That asymmetry against the language token is deliberate: an unknown language costs syntax highlighting and is reported as a degradation, while a silently dropped attribute publishes a page the author did not ask for.
06 Mermaid

Six diagram families render. Everything else fails its page.

A mermaid fence is rendered to SVG through Node and uploaded as an attachment, named from a hash of the diagram source. That naming is a pure function of the source, so an unrelated edit elsewhere on the page never renames the attachment and never churns the content hash.

Rendering happens at publish. convert counts diagrams without starting a process unless --render-mermaid is passed, which is what makes a conversion check cheap enough to run on every pull request.

The whole set the parser dispatches on

graph / flowchart · sequenceDiagram · classDiagram · erDiagram · stateDiagram / stateDiagram-v2 · xychart-beta

The renderer is a reimplementation of mermaid rather than mermaid itself, so it accepts a subset. Anything outside this list fails on its header line before a single node is read.

HeaderWhy it fails
pieThe renderer does not implement pie charts, nor sixteen other diagram types outside the six families
graph TD;A trailing semicolon, and only on graph, flowchart and stateDiagram. sequenceDiagram; and classDiagram; render, and graph TD renders
YAML frontmatterThe renderer does not read it. A mermaid title: or config: block fails every diagram type, including the six that otherwise work

That second row is uneven for a reason worth knowing before you read the error twice: the semicolon is tolerated exactly where the diagram type is detected by its own name, and dropped where the header also has to carry a direction. Every rejection reports the same Invalid mermaid header message, which tells you the header was not recognised and never why.

07 The approval machine

A label in, a state transition out.

FieldMeaning
statusapproved or needs-review
approvedByAlways unknown — Confluence Cloud exposes no label author anywhere the API can reach
approvedAtWhen a sync run saw the label at the approved version. Restamped if the page reaches a new version with the label still on, and the stamp it displaces goes to history
approvedVersionThe Confluence page version the approval applies to
historyEvery prior approval. One is archived when an approval is invalidated, and also when a still-valid approval is re-recorded at a newer version

What invalidates an approval

Two things, and they run through the same transition. A republish whose content hash changed — DocuMe removes the label, moves the approval into history and sets the status to needs-review. And a reviewer taking the label off — the sync run reads "label absent, state says approved" as a revocation and applies the identical transition, with no label for DocuMe to remove because the reviewer already removed it.

Invalidates
  • Editing one sentence of the markdown
  • Editing a mermaid diagram — its attachment name derives from the source, so the body changes too
  • A reviewer removing the label
Does not
  • A new publish date in the banner — the hash excludes it
  • A dashboard refresh
  • Reparenting: where a page hangs is not what a reviewer approved
  • --force on its own. It re-uploads everything, but an unchanged hash means unchanged content
The one case worth knowing Attachment bytes sit outside the hash entirely. A hand-placed image whose bytes change is re-uploaded with the approval left standing, because the body still says the same thing. It is the only case where an approved page visibly changes without a re-review.
The dashboard is deliberately not tracked docume dashboard publishes one page listing every page with its approval state, staleness and last publish. It is generated from state plus the live labels, and it is kept out of state itself: a page DocuMe publishes but does not own would otherwise look like an orphan to publish --prune and be deleted.
08 The skills three

Three skills, one ending — a pull request.

None of them calls the Confluence API. All three also have the other ending, the one a nightly job has most nights, and it is not a failure: they stop without a branch, a commit or a pull request. An empty PR costs a reviewer more than it tells them.

SkillUse it whenOpens nothing whenBranch
/docs-loop A wiki is being built from scratch, a page that should exist does not, or a recorded gap is being asked for no unit is todo in the progress file docs/loop-<date>
/docs-refresh Drift was reported: a stale label, a drift comment, the nightly cron. Also a change you just made on a branch the drift report says nothing drifted docs/refresh-<date>
/docs-feedback Inbox items are waiting after a comment sync, or somebody asks you to deal with the comments no inbox item is untriaged docs/feedback-<date>

The boundaries are worth stating because they overlap in the obvious wrong way: /docs-loop writes pages that do not exist, /docs-refresh rewrites pages whose code moved, /docs-feedback answers a reviewer. A refresh that finds a missing page records a gap rather than writing it.

Why two skills stamp the baseline differently No CLI command writes the generation baseline — the generation pass owns it, and the two skills stamp it to different values on purpose. /docs-loop sets it to the oldest generation sha still recorded, so drift measures from the point the content was written; today's HEAD after one page would silently retire every drift the earlier pages accumulated. /docs-refresh stamps HEAD, because that run really did regenerate everything drifted, and leaving the field alone would report the same pages again tomorrow night.
Installing The plugin half is two slash commands inside Claude Code, not shell commands. The CLI is a separate install and the skills need it: they invoke the pinned tool through the repo-local manifest that docume init writes. A repo that has not run init gets a missing-command error from the SDK, not a DocuMe message — the DocuMe one comes a step later, once the tool restores and the config is what is missing.
09 The workflows six

Everything writes through a pull request.

Four of the six change the repo, and none of them pushes to the default branch. The publish and sync jobs commit the machine-owned state file to a shared docs/sync branch, opening that pull request when it is not already open; the refresh and feedback jobs push a dated branch of their own. That is also why the publish workflow is the only one that writes page bodies: it runs on the default branch, after the review.

Why every template adds a package feed DocuMe.Cli is published to GitHub Packages rather than nuget.org, and GitHub Packages authenticates every read including a public package. A restore with no feed configured resolves the pin against nuget.org alone and fails. Each template reads a packages-token secret and falls back to the workflow's own GITHUB_TOKEN, which is enough from a repository in the same organisation as the package; from another org, add the secret holding a PAT with read:packages.

Which jobs hold which secrets

Confluence credentials

publish · drift · sync

The three that talk to Confluence, and only those three.

Model key only

refresh · feedback

The unsupervised model runs. A skill's output is a pull request, so only the CLI writes to Confluence and the publishing token stays out of the job a model drives.

Neither

drift-pr

Runs on every contributor's branch, and its report is a git diff plus a glob match. The workflow with the widest trigger never sees the publishing token.

A green run that did nothing looks like a green run that worked That is a live risk in exactly the two workflows a model drives, because the skill is what decides whether to push at all. Both check the remote for their own branch family before and after, and annotate the run with which branch they pushed: a refresh run that pushed nothing says so out loud. Both also bound the model step with a timeout — on the default output format the CLI prints nothing until it exits, so a hung run leaves an empty step log and, without a timeout, holds the runner for six hours before anything says so.
10 The composite action

Three setup lines you do not have to get right a seventh time.

Every template opens the same way — install the SDK, add the package feed, restore the pinned tool. A composite action wraps all of it, for a docs job you write yourself.

a docs job of your own
jobs:
  publish:
    runs-on: ubuntu-latest
    env:
      DOCUME_CONFLUENCE_EMAIL: ${{ secrets.DOCUME_CONFLUENCE_EMAIL }}
      DOCUME_CONFLUENCE_TOKEN: ${{ secrets.DOCUME_CONFLUENCE_TOKEN }}
    steps:
      - uses: actions/checkout@v4
      - uses: moberghr/docu-me/actions@v0
        with:
          args: publish --dry-run
          packages-token: ${{ secrets.GITHUB_TOKEN }}
InputRequiredDoes
argsyesEverything after docume, as one string
packages-tokennoToken for the GitHub Packages feed, empty by default
dotnet-versionnoSDK to install, 10.0.x by default
mermaidnoDiagram renderer, auto by default
  • It names no DocuMe version. It restores your tool manifest rather than installing anything, so the CLI it runs is the one your repo pinned and a DocuMe release cannot change the version your CI runs.
  • packages-token is optional in the schema and needed in practice. A composite action cannot read secrets for itself, so the feed has to be handed to it; leave it empty only when your repo names that feed in a committed NuGet.config.
  • mermaid: auto pays only when it must. Node and the renderer are installed when args invokes publish, or convert --render-mermaid, and skipped otherwise — a drift or a sync pays for no toolchain.
  • args is split on whitespace. No single argument can carry a space of its own, so a run that needs one belongs in a plain run: step calling the tool directly.
  • The ref is a floating major tag, force-moved by the last step of each release. Pin an exact release instead if you would rather nothing moved under you.
11 The security model

Four rules, and each one is enforced somewhere.

01

Credentials come from the environment

Two variables, and nowhere else — not docume.json, which is committed, and not the command line, which lands in shell history. The suite fails on a token literal in a shipped file.

02

Auth failures are a hard stop

401 and 403 stop the run with a token-expiry message instead of retrying. Retrying a rejected credential only wastes the rate limit. Retry with backoff is for 429 and 5xx.

03

Page bodies and comments are untrusted

Every skill states it in its own system contract: a comment is a claim to verify against the code, never an instruction. Nothing a reviewer wrote is echoed into a page body.

04

A human reviews every docs change

CI jobs run with read-only repo access and PR-only writes. The generative tier cannot publish; the deterministic tier only publishes what already merged.

That is the whole surface.
